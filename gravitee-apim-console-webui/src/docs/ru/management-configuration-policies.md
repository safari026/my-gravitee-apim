# Policy studio

## Дизайн

Политики позволяют настраивать и расширять поведение и возможности API. Они могут обеспечивать безопасность, повышать производительность, преобразовывать запрос и ответ и выполнять логику через Groovy Policy или dynamic routing policy.

Политики можно объединять в цепочку и применять к корневому пути (/**) или к отдельным путям.

Политику можно перетащить в центр экрана, чтобы применить её к пути. Справа настраиваются параметры политики.

Кнопка (+) создаёт новый путь и задаёт его поведение через политики.

## Конфигурация

Как пользователь организации вы можете задавать platform flows.

Каждый flow применяется к пути в заданном порядке.

Можно указать имя и описание. Если имя пустое, оно будет составлено из оператора ("Starts with" или "Equals"), пути и HTTP-методов.

Можно указать один или несколько sharding tags.
Flow выполняется только для API, у которых есть совпадающий sharding tag.
Если список пуст, flow выполняется для всех API.

Также можно задать условие на Expression Language (EL).

Этот язык позволяет запрашивать и изменять граф объектов и основан на SpEL (Spring Expression Language). Всё, что описано по ссылке, доступно и здесь.

##### Примеры:
- Значение свойства my-property из properties: `{#properties['my-property']}`
- Значение заголовка Content-Type входящего HTTP-запроса: `{#request.headers['content-type']}`
- Вторая часть пути запроса: `{#request.paths[1]}`
- Значение атрибута user-id входящего HTTP-запроса `{#context.attributes['user-id']}`
- Значение атрибута plan входящего HTTP-запроса `{#context.attributes['plan']}`
